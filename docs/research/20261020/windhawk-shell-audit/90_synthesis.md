# Windhawk PowerShell audit synthesis

The local scan found 22 `.wh.cpp` files with a PowerShell-related token. Only two contain mod-owned PowerShell implementations that should be replaced: `net-toggle.wh.cpp` and `uwp-assets-redirect.wh.cpp`. Six files expose intentional user-facing PowerShell or script execution and must retain it for compatibility: `auto-theme-switcher.wh.cpp`, `magic-mouse.wh.cpp`, `open-in-admin-terminal.wh.cpp`, `separate-system-tray-icons.wh.cpp`, `ultimate-custom-tray.wh.cpp`, and `windows-11-start-menu-buttons.wh.cpp`. The other 14 matches are documentation, samples, identifiers, visual style data, or a search false positive. The C++ source tree under `vendor/windhawk` has zero matches; its Python keybinding helper and JSON error fixture are C-class out-of-scope references.

Evidence is recorded in [10_discovery.md](10_discovery.md); primary API checkpoints are in [20_sources.md](20_sources.md). The source snapshot was commit `b692673878190524ef11501075fd084411348154`; no vendor source was changed during this audit.

## A-class replacement plan

`net-toggle.wh.cpp` owns two operations. `WorkerThreadProc` (lines 769–772) disables or enables every physical network adapter through `Get-NetAdapter -Physical | Disable-NetAdapter` or `Enable-NetAdapter`. `ResetWorkerThreadProc` (lines 807–829) performs the same adapter cycle, sleeps for two seconds, and runs `ipconfig /flushdns`. Both are launched by `RunPowerShellCommand` (lines 274–334) through an elevated `powershell.exe` process.

The native implementation should enumerate present devices in `GUID_DEVCLASS_NET` with [`SetupDiGetClassDevsW`](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdigetclassdevsw) and [`SetupDiEnumDeviceInfo`](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdienumdeviceinfo), preserve the existing physical-adapter filter, and apply [`CM_Disable_DevNode`](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_disable_devnode) or [`CM_Enable_DevNode`](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_enable_devnode) per device. The [`DIF_PROPERTYCHANGE`](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/dif-propertychange) plus [`SetupDiCallClassInstaller`](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdicallclassinstaller) route is the alternative if class/co-installers must participate; it also requires restart-flag handling. Use transient flags and do not persist disable state. The current mod’s medium-integrity injected context may not be able to change device state, so retain the existing UAC behavior through a native elevated helper launched with [`ShellExecuteEx`](https://learn.microsoft.com/en-us/windows/win32/shell/launch) using the `runas` verb and [`SEE_MASK_NOCLOSEPROCESS`](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfoa). The official `windns.h` index did not expose a public `DnsFlushResolverCache` entry; keep `ipconfig /flushdns` as a separately invoked dependency until an SDK/runtime export is verified, or omit only if reset semantics are deliberately changed.

`uwp-assets-redirect.wh.cpp` owns the permission grant in `CheckWindowsAppsOwner` (lines 2339–2461). Its hardcoded `g_ownership_command` (lines 2331–2337) starts PowerShell, which starts elevated `cmd.exe`, which runs `takeown` and `icacls` against `C:\Program Files\WindowsApps`. A minimal migration can launch `cmd.exe /c` directly with `ShellExecuteExW` and `runas`, preserving UAC and the existing command semantics. A full native migration can use [`GetNamedSecurityInfoW`](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getnamedsecurityinfow), [`SetEntriesInAclW`](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setentriesinaclw), and [`SetNamedSecurityInfoW`](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setnamedsecurityinfow) in an elevated helper. Resolve the Administrators and current-user SIDs explicitly, preserve the `takeown /A` owner change and current-user read grant, check return codes, and free all ACL/security-descriptor buffers. The unrelated icon-cache `cmd /c` action in lines 497–509 contains no PowerShell and remains outside this replacement.

## B-class compatibility that must remain

`auto-theme-switcher.wh.cpp:352–370` launches the user-configured `.ps1` path with `-File` and `-light`/`-dark`. `magic-mouse.wh.cpp:3138–3167` opens the user-selected elevated PowerShell terminal and appends the optional user command. `open-in-admin-terminal.wh.cpp:363–371,789–916,2092–2174` resolves the configured PowerShell 7/Windows PowerShell host, opens it in the requested directory, and runs selected `.ps1` files. `separate-system-tray-icons.wh.cpp:953–983` implements user-authored `ps:`/`powershell:` actions. `ultimate-custom-tray.wh.cpp:710–753` and `windows-11-start-menu-buttons.wh.cpp:1132–1157` implement user-authored `shell:` actions with optional elevation and visible terminal behavior. Removing or silently rewriting these paths would break explicit compatibility requirements.

For `open-in-admin-terminal`, `Set-Location` is internal directory initialization, so a later implementation may use `SHELLEXECUTEINFO.lpDirectory` when a host honors it. The PowerShell executable, `.ps1 -File` behavior, optional `-ExecutionPolicy Bypass`, terminal selection, and user command text remain required. `magic-mouse`’s separate Run Command Line action already uses `COMSPEC`/`cmd.exe`; it is not an internal PowerShell dependency.

## Source-based acceptance tests

These checks are read-only or compile-only. They do not toggle a network adapter, create a service, launch a shell, change an ACL, or modify the desktop.

1. Re-run the inventory and assert that the 22 mod files and zero `vendor/windhawk` C++ files are accounted for. The expected classification is A=2, B=6, C=14.
2. After migration, scan only the A files and assert that no executable string or function remains for `powershell.exe`, `RunPowerShellCommand`, `Get-NetAdapter`, `Enable-NetAdapter`, `Disable-NetAdapter`, `Start-Sleep`, or the PowerShell `g_ownership_command`. Comments should be updated so the scan does not hide stale implementation references.
3. Assert native replacement symbols in the A files: network code must contain `SetupDiGetClassDevsW`/`SetupDiEnumDeviceInfo` and either `CM_Disable_DevNode`/`CM_Enable_DevNode` or the documented `DIF_PROPERTYCHANGE`/`SetupDiCallClassInstaller` path; UWP permission code must contain the chosen direct `ShellExecuteExW`/`runas` or ACL API path and no PowerShell wrapper.
4. Assert that each B file still contains its compatibility marker: `.ps1` + `powershell.exe -File` in Auto Theme Switcher; `ACTION_ADMIN_TERMINAL` + elevated PowerShell in Magic Mouse; `pwsh`/`powershell` choices and `.ps1` interpreter handling in Open in Admin Terminal; `ps:`/`powershell:` in Separate System Tray Icons; `shell:` in Ultimate Custom Tray and Windows 11 Start Menu Buttons.
5. Compile the changed native C++ translation units or helper with `/c` only and link against `Cfgmgr32.lib`, `Setupapi.lib`, `Shell32.lib`, and `Advapi32.lib` as applicable. Do not run the resulting helper in the acceptance test.
6. Use source-level unit tests for command-line/ACL/device-selection builders with mocked API callbacks. Verify quoting, physical-device filtering, transient flags, per-device failure propagation, UAC cancellation handling, and current-user SID resolution without calling the live APIs.
7. Run `git diff --check` and a package/source scan to ensure no PowerShell removal touched the B files or changed unrelated ThemeStudio/NoSeelen/0.5 source.

No product code was modified in this audit. The only files written are the four notes in this research folder.
